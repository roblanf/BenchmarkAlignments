# BenchmarkAlignments: notes for agents

This repository is a curated database of phylogenetic alignments with rich metadata.
Read this file, then `docs/ADDING_A_DATASET.md`, before touching anything.

## Layout

- `datasets/<Name>/` one folder per dataset. Tracked: `README.yaml`, `charset.csv`,
  `alignment.nex-summary.txt`, `alignment.nex-seq-summary.txt`. **Not tracked** (gitignored):
  `alignment.nex` and any `*.pdf`. The alignments are hosted on figShare.
- `new_dataset_files/README.yaml` the template for a new dataset's metadata. The schema is
  enforced by `utility_scripts/validate_dataset.py`; do not add, rename or drop keys.
- `utility_scripts/` the pipeline. Start with `validate_dataset.py --help`.
- `summary.csv` one row per dataset, regenerated by `build_summary_csv.py`. Never edit by hand.
- `docs/` the full procedure for adding a dataset and the list of known legacy issues.

## Environment

Everything runs in the `benchaln` conda env defined in `environment.yml`:

```bash
conda env create -f environment.yml
conda run -n benchaln Rscript utility_scripts/install_datelife.R   # DateLife is not on conda
export BENCHALN_DATA=/path/to/alignments   # folder holding <Name>/alignment.nex for every dataset
```

On Rob's machine `BENCHALN_DATA=/home/rob/BenchmarkAlignments_data`. If `conda run` picks
up another env's python, call the binaries by absolute path, e.g.
`/home/rob/anaconda3/envs/benchaln/bin/python`.

## Rules that are not negotiable

1. A dataset is only added when every check in `validate_dataset.py` passes with network on.
2. Nothing in README.yaml stands until you have read the paper in full, including every
   relevant supplement, and the metadata page of the data repository. The methods section
   alone is not enough: outgroups, excluded taxa, partition schemes and whether a
   concatenated tree was inferred are often only in supplements or figure legends. Do not
   assume a value (for example `concatenated: no` because the study used ASTRAL) without
   having read the whole paper.
3. Nothing in the metadata is guessed. Every value is read from the paper, its supplement,
   the data repository, or computed from the alignment. If something cannot be found, ask
   Rob and keep asking until it is resolved. Do not fill a field with NA to make a test pass,
   except where `docs/ADDING_A_DATASET.md` explicitly says NA is allowed.
4. The paper and supplement PDFs live beside the dataset as `datasets/<Name>/*.pdf`. They are
   gitignored. Rob drops PDFs in `pdfs/` at the repository root (also gitignored); move
   them into the dataset folder and name them `<Name>_paper.pdf`, `<Name>_supplement.pdf`.
   If they are missing and the paper is not open access, ask Rob for them. Publisher sites
   block automated PDF downloads; do not spend long trying.
5. Divergence times come from DateLife (`utility_scripts/datelife_query.R`) and from the
   study itself (`study root age`). timetree.org is not used for new datasets.
6. Every codon-position annotation is verified by translation (`check_codon_frames.py`),
   never assumed from a partition file.
7. Record every judgement call and every edit to the data in `README.yaml`
   (`dataset curation` and `notes`), and summarise them for Rob in the pull request.
8. Work on a branch named `dataset/<Name>`; one dataset per branch and pull request.
9. Do not upload to figShare; Rob does that. Leave `figshare: NA` and say so in the PR.
